# 问题3 / 问题4 求解器 (`robotdog/solver/`)

机器狗从原点出发，在半径 1800 m 的圆域中自主搜索、定位并清除 10~16 个无线电干扰源，
目标是在**确保全部清除的前提下总时间最短**。

**每题只有一条策略，没有候选与版本之分**：

| 题目 | 求解器 | 机制 |
| --- | --- | --- |
| 问题3（全向源） | **`sweeper.py`** | 清除即探测：就近清除已知源 + 清除后原地补测 + 信息收益专程探测 + 集合覆盖收尾 |
| 问题4（含定向源） | **`sweeper4.py`** | 24 点集合覆盖补扫 + 沿示向度射线一维盲清 + 贴边补扫环 |

## 1. 题目理解：这到底是个什么决策问题

| 题目要素（附件1/附件2） | 对策略的含义 |
| --- | --- |
| 域内 10~16 个源，频道互不相同（20 个频道里选），个数未知 | 必须**自己判断还剩几个源**：用「每个频道存在未清除源的概率 π_c」做贝叶斯推断，Σπ_c 即剩余源数的期望 |
| 有效接收半径 R ~ U(1000,1500) m，**且不返回** | 距离超过 R 检测不到。因此 R 既是「要靠近才能发现」的约束，也可由观测反推：在距离 d **收到**信号 ⇒ R ≥ d；在距离 d **收不到** ⇒ R < d |
| 示向度误差 ∈ [-1°,1°]，**同一检测点读数固定** | 单次读数只是一条「射线」约束（横向准、纵向完全未知）。同一地点重复检测零信息 —— 策略必须显式排除已测过的点 |
| `/measure` 同时包含移动 + 切频道 + 检测（5 s，切换 1 s） | 一个动作 = 「到某点测某频道」。移动 5 m/s 是**时间主项** |
| `/clear` 半径 20 m，命中 5 s / 未发现 3 s，不切换频道 | 必须真实逼近到 20 m 内；未命中只花 3 s，且「该点 20 m 内无源」本身是硬信息 |
| 距离 ≤ 5 m 时返回 `near`（无示向度） | `near` 是「中奖」信号：源就在 5 m 内，原地清除必成 |
| 平均值口径 = 总时间 / 已清除数 | 少清一个源会**双重惩罚**（分子变小、分母不变），因此漏源比慢更不可接受 |
| 虚拟时长上限 100 h 只为防死循环；现实上限 20 min | 现实 1 s 可推进任意多虚拟秒（实测约 1:38000），**时间优化就是虚拟时间优化** |

**结构结论**：单局时间构成实测约

| 项 | 占比 |
| --- | --- |
| 移动（探测段 + 逼近段） | **约 71%** |
| 检测 5 s/次（一局约 135 次） | 约 22% |
| 清除 3~5 s/次 | 约 2% |
| 频道切换 | 约 5% |

所以策略的全部难点是**少走路**：既要把路走在「去清除」上，又要顺路把还没发现的源找出来。
逼近移动几乎不可压缩，可压缩的是「探测段移动」。

## 2. 问题3 的核心洞察：清除即探测

`sweeper` 只有一条设计主线，其余都是从它推出来的：

> 平均每局 13.1 个源均匀分布在 r=1800 的圆域里，**最近邻距离中位 451 m（均值 494 m）**，
> 第 3 近邻中位 944 m（均值 992 m）—— 而有效接收半径 R ≥ 1000 m。
>
> 因此**站在一个刚清除的源上测其它频道，对附近未发现的源几乎是「必中」**
> （d ≤ 1000 m 时 P(收到) = 1），而且这一步**零额外移动**。

反过来，在「去目标路上 60% 处」测（P(检测) ≈ 0.3）或专程跑到格点上测，实测每局有
约 104 次 `no_signal`（624 s），外加约 4740 m 专程探测移动（948 s）——几乎全是浪费。

于是策略变成：**永远就近清除已知源（路线 ≈ TSP），清除成功后原地补测一圈其它频道。**
搜索与清除不再是两件事，而是同一趟路。

## 3. 形式化：带信念的决策问题

真值（源的位置、频道、R）不可观测，因此严格来说是 POMDP。本方案把问题拆成
「**估计**（贝叶斯，非学习）」+「**决策**（确定性规划）」两层。

### 3.1 信念：三种表示（`belief.py`）

| 情形 | 表示 | 更新 |
| --- | --- | --- |
| 还没收到过示向度 | 100 m 分辨率**占用网格** | `no_signal` 乘核 `P(R<d)=clamp((d-1000)/500)` |
| 只有一条示向度 | 沿射线的 **128 个一维样本**（径向密度 ∝ r·P(R≥r)） | 一维重加权 + 系统重采样（固定相位，保证可复现） |
| ≥2 条示向度 | **Gauss-Newton 角度残差最小二乘** + 解析协方差 `Σ=(JᵀJ/σ²+先验)⁻¹` | O(观测数) 迭代，σ=0.5774°（对应 U(-1°,1°)） |

同时维护每个频道的存在概率 π_c，用 `P(观测|存在)` 做贝叶斯更新。

**为什么不用粒子滤波**：一条 ±1° 射线把后验压成宽约 20 m 的窄楔形，在 1.0e7 m² 上用
200 个粒子，落在楔形内的期望不足 1 个 —— 必然退化（本项目实测确认）。

### 3.2 动作：四个原语（`ops.py`）

| 原语 | 语义 |
| --- | --- |
| `pursue(c)` | 对频道 c 执行「逼近—检测—清除」子策略，直到清除 / 失败 |
| `pursue_fast(c)` | 逼近时沿视线推进（本来就要走），在需要时于剩余路段中点做一次弦式侧移检测（δ 按后验纵深不确定度定标，限制在 10~400 m）把纵向距离定下来 |
| `probe(p, chans)` | 移动到点 p，对筛选后的频道做一轮检测 |
| `best_info_point` | 需要专程探测时按**净收益 = 信息价值 − 旅行 − 检测**选点，亏本的不去 |

`pursue` 内部的「下一点测哪里」用一步前瞻贪心（`ops.choose_measure_point`）：
代价 = 去检测点的移动 + 之后到新估计点的移动 + 权重 × **按检测概率加权**的后验不确定度。
关键几何：一次检测只约束「源在某条射线上」，要压缩最不确定方向 v，新检测点的**视线必须与
v 垂直**（沿视线挪动零信息）；再叠加「检测概率」权重，才不会退化成「原地反复检测同一点」。

### 3.3 主循环（`sweeper.run_sweeper`）

```
1. 起点盲扫一次        (原点覆盖半径 1000~1500 m, 命中约一半源)
2. 有已定位目标 → 就近清除 (TSP 排序), 逼近途中只测目标频道用于定位
3. 清除成功后 → 原地补测其它可疑频道 (零移动, 收益最高的一步)
4. 没有已知目标 → 按信息净收益专程探测; 都不划算则按集合覆盖扫残余质量
5. 收尾: 残余期望源数 < hunt_mass_min 或连续 hunt_fail_max 次探测无收获则收手
```

**正式测试看不到真值总数**（真值屏蔽），因此第 5 步只能用信念信息判断何时收手 ——
这正是 `run_sweeper(..., knows_total=False)` 的含义，也是部署与进程内评测的唯一口径差异。

### 3.4 单点联合选择

「顺路停车点」与「弦式侧移」本来是两个手挑决定，现在由同一条规则
（`joint_measure_point`）接管，在一条 leg 上联合选**一个**测点：

```
min  实际旅行秒(经过 q 再走向目标) + 6 s 检测 + E[剩余清除代价 | 后验]
```

候选集恒含"不联合"时会选的那个点，因此模型认为联合更差时会自动退回，不会因为模型偏差变坏。

### 4.2 端到端（真实模拟器进程 + HTTP + 真值屏蔽）

不指定 `--seed` 时每局随机抽案例，**约 94% 的局全部清除，未全清的局通常只漏 1 个源**
（漏源与标定集的 0.9955 是同一回事，不是端到端口径的额外损失）。

三种计时口径的实际占用：

| 口径 | 上限 | 实际 | 余量 |
| --- | --- | --- | --- |
| 虚拟世界活动时长 | 360000 s | 约 4400 s | 用掉 **1.2%** |
| **现实程序运行时间** | **1200 s** | **约 0.1 s** | 用掉 **0.008%** |

**现实 : 虚拟 ≈ 1 : 38000。时间预算根本用不完，瓶颈是「还能不能找到剩下的源」。**

### 4.3 时间与移动去哪了（`tools/profile_run.py`）

单局虚拟时间中约 **72% 是移动**，pursue（逼近/定位/清除）一个阶段就占移动的约 69%。
`tools/move_bound.py` 用真值算精确 TSP 给出移动下界：实际移动约为下界的 **1.25 倍**，
差距主要来自顺序、接近绕行与收尾覆盖 —— 用 `--trace 1` 可以逐局看策略的每一步决策。

## 5. 参数标定

`build_cfg()` 是评测与部署**共用的唯一一份**参数。唯一重要的旋钮是**收尾闸门**
`hunt_mass_min`：残余期望源数低于它即收手。

残余期望源数落在 [0.02, 0.20) 时，每次专程探测的命中率只有 0.9%~3.2%，代价却是
166~203 s 的往返，因此按「清除比例 ≥ 0.98」的判据把它标定为 **0.20**（2000 局标定集上
清除比例 0.9955，余量 +0.0155）。`probe_max` / `hunt_fail_max` / `max_actions` /
`max_virtual` 实测**从不成为约束**，是纯安全阀。

## 7. 工程要点（踩过的坑，全部有据可查）

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 粒子滤波完全退化，估计不可用 | ±1° 是**硬约束**，窄楔形面积占全域 0.4%，200 粒子必然只剩 0~1 个 | 改为「网格 / 射线样本 / GN 解析」三表示混合 |
| 协方差只有 9 m 但真值差 400 m | 后验信息矩阵漏了 σ² 量纲，先验正则被放大 1/σ² 倍 | `Σ=(JᵀJ/σ²+先验)⁻¹` |
| 智能体原地反复检测同一个点 | 不知道「同点同频道读数不变」；打分函数没算检测概率 | 记录已测点并排除；不确定度按检测概率加权 |
| 已定位源被放弃，清除率卡在 ~98% | R 的后验只用了 `no_signal` 给的上界，**漏了「收到过信号」给的下界** | `r_bounds()` 同时用两侧观测 |
| 远距离 `no_signal` 反而让 π 崩塌 | 检测概率积分写成了 `E[F_R(d)]`（自己的补集） | 改为 `1 - E[F_R(d)]` |
| 同一案例两次跑出 13% 抖动，评测不可比 | 射线重采样用**无播种**随机数 | 改系统重采样（固定相位），现在逐位可复现 |
| 个别种子跑成上万秒、只清一半 | `pursue_fast` **没有停滞保护**，假轨迹被无限重试 | 连续 3 步没有新观测就放弃；外层再加「没清掉且没新观测 ⇒ 拉黑该频道」 |
| "优化得更优"的巡回反而慢 37% | 单射线目标不确定度大，静态最优解会把机器人派去远处省名义长度 | 保留最近优先启发式（对真值巡回的遗憾只有 0.59%，且在重规划下稳健） |
| 把"顺路停车"的移动算成"专程探测移动" | `leg_info_stop` 选的停车点落在去目标的**直线段**上 | 阶段剖析按"是否在 leg 内"归类 |

## 8. 问题4：含定向干扰源（`sweeper4.py`）

**解法全文见 `docs/问题4解法.md`**。这里只给结论。

### 8.1 物理上多出来的唯一一条规则，改变了三件事

定向源只在 **定向方向 ψ 两侧各 90°** 内辐射（全向源视为恒满足）。由此：

| | 问题3 | 问题4 |
| --- | --- | --- |
| 单点发现概率（ψ 未知，$d\le R$） | **1** | **1/2，且与距离无关** |
| `no_signal` 的含义 | 这里没有源（距离超限） | **要么太远、要么被波束背对** |
| 保证发现的探测点间距 | ≤1732 m（1-覆盖） | **≤1000 m（还要求角向无 180° 空隙）** |

"1/2 且与距离无关"是问题4 最反直觉的一条：**把狗挪到 50 m 处也不会提高发现概率**，
只有换方位才有用。这就是为什么问题3 的 "站在刚清除的源上补测" 在问题4 只剩一半命中率。

### 8.2 三个机制

* **24 点贪心集合覆盖补扫**：把「位置 P × 定向方向 φ」当全集（150 m × 20° 网格，
  7938 个元素），扫描点 Q 覆盖 (P,φ) ⟺ `|Q−P| ≤ 1000` 且 Q 在 φ 的 ±90° 内。
  贪心求最少点集 → **24 点覆盖 99.94%**。
* **沿示向度射线的一维盲清**：`/clear` 只判距离、与覆盖角无关，所以"在 P 点收到过
  频道 c 的示向度 b"就意味着源在过 P、方向 b 的直线上 —— 沿射线按 35 m 步长采样
  盲清即可，把二维搜索降成一维。每个采样点再做 ±0.3° 横向摆动（偏移 < 20 m）。
* **贴边补扫环**：半径 1785 m、24 点（每 15°）。它把清除比例从 0.9996 推到 **1.0000** ——
  残余漏源的形状是"贴着竞技场边界的一条弧带"，非贴边的点够不到。

### 8.3 成绩

标定集 seed 9500-9799（300 局，3935 个源，其中定向 1952）：

| 档位 | 清除比例 | 全清局 | 平均定位清除 | 移动 |
| --- | --- | --- | --- | --- |
| **全清档（默认）· 进程内 = 部署（逐位相同）** | **1.0000** | **300/300** | 1819.8 s/源 | 95 241 m |
| 极速档（`boundary_ring=False`） | 0.9997 | 299/300 | 1340.2 s/源 | 70 495 m |

独立测试集与全新种子（全清档，部署口径）：**8000-8099 → 1.0000（100/100）· 9000-9099 →
1.0000（100/100）· 20000-21999 → 1.00000（2000/2000）**。合计 **2500 局、31 000+ 个源、
零遗漏**。
