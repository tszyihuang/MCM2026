# 机器狗程序 (`robotdog/`)

本目录是 B 题的**机器狗端程序**：一层与模拟器通信的 HTTP 客户端，加两条互不依赖的求解策略。

> **本目录只保留当前发布的策略**（每个问题各一份）。历史上的中间版本已移出，见文末
> 「整理记录」。策略的设计推导、实验数据与踩坑清单见 [`solver/README.md`](solver/README.md)。

---

## 1. 当前策略（最新，唯一在用的两份）

**两题都是「100% 清除」档**：问题3 靠 1000 m 覆盖收尾的命题保证，问题4 靠 22 站环骨架的
零漏检几何判据。下表成绩全部是**部署口径**（`knows_total=False`，与正式测试一致）。

| 问题 | 策略模块 | 方案要点 | 实测（部署口径） |
| --- | --- | --- | --- |
| **问题3**（全向源） | [`solver/sweeper.py`](solver/sweeper.py) | 清除即探测：就近清除已知源，清除后原地补测其它频道；无已知目标时按信息净收益专程探测，最后按 1000 m 集合覆盖收尾（`coverage_finish=True`） | **清除比例 1.0000，全清 7000/7000 局，377~379 s/源**（标定 2000 局 + 独立/全新 5000 局） |
| **问题4**（含定向源） | [`solver/sweeper4.py`](solver/sweeper4.py) | 22 站零漏检环骨架（原点 + 985 m×7 + 1850 m×14）+ 中继测量（第 2 条示向度顺路插在腿内，零额外移动）+ 加权最小二乘交会定位 + 在线路线重优化（2-opt / Or-opt / cheapest insertion） | **清除比例 1.0000，全清 5500/5500 局，450.8~452.6 s/源**（标定 500 + 独立 1000 + 全新 4000 局） |

两条策略共用通信层、物理常量与进程内环境，但**不共享任何策略状态**，可以各自独立评测与部署。

**100% 是怎么来的（不是靠调参碰运气）**

| 问题 | 保证机制 | 判据 |
| --- | --- | --- |
| 问题3 | 1000 m 覆盖收尾：`coverage_finish=True` + `hunt_mass_min=0.00` | 题目给定 R ≥ 1000 m，所以"每个未清除频道在圆域内处处被一组测过它的测点以 1000 m 覆盖" ⇒ 该频道的源必已被发现 ⇒ 停机即不漏源（推导见 `docs/问题3论文.md` §3.3 命题 1） |
| 问题4 | 22 站零漏检骨架：`ring_def = ((0,1,0.0),(985.0,7,0.0),(1850.0,14,4.286))` | 以最坏接收半径 R = 1000 m 做全方向覆盖审计，最坏角隙 **178.99° ≤ 180°** ⇒ 不存在"任何站点都看不见"的（位置, 定向方向）组合（`tools/probes/q4_opt1_layout.py`；抽样 260 109 个源，0 个看不见） |

问题4 若愿意用清除率换速度，可把 `sweeper4.PARAMS['ring_def']` 换成 16 站
（`((0, 1, 0.0), (985.0, 5, 0.0), (1850.0, 10, 4.286))`）：快约 6.3%（422.3 s/源），
但最坏角隙 360° ⇒ 存在漏检方向，实测清除比例 0.9992。**当前发布取 22 站**。

## 2. 目录结构

```
robotdog/
  consts.py                 题目物理常量（唯一来源，供客户端与求解器共用）
  geometry.py               方位角 / 交会 / 加权角度残差最小二乘（纯标准库）
  client.py                 RobotClient: HTTP+JSON 客户端（重试 / 幂等 / 现实预算 / 行为日志）
  __init__.py               包入口，导出 RobotClient

  solver/                   求解器（需 numpy）
    sweeper.py              ★ 问题3 规划器（当前发布）
    belief.py               问题3 信念：占用网格 / 射线一维样本 / Gauss-Newton 三表示
    ops.py                  问题3 动作原语：pursue / pursue_fast / probe / 候选点 / 收益评估
    sweeper4.py             ★ 问题4 规划器（当前发布 = 22 站零漏检档，含单文件策略适配层）
    belief4.py              问题4 信念（位置三表示 + 源型 λ + 定向方向 ψ 分箱）
    scan4.py                问题4 补扫点集几何（六边形网格 / 环 / Held-Karp 巡游 / 覆盖审计）
    world.py                进程内精确复刻环境（问题3/问题4，真值与可观测信息严格分离）
    deploy.py               部署入口：python -m robotdog.solver.deploy --problem 3|4
    eval.py                 问题3 进程内评测入口（多核并行 / --trace 逐步明细）
    e2e_test.py             真实进程 + HTTP 端到端验收（--problem 3|4）
    oracle_route.py         已知路线下界探针（论文取数）
    opt1_port.py            单文件策略（strategy(ctx) 形态）适配层（实验用，不在发布路径上）
    opt1_deploy.py          上者的部署入口
    README.md               求解器总说明（建模、算法、结果、参数标定、踩坑清单）
```

`belief4.py` 目前**不被任何模块导入**：当前发布策略 `sweeper4.py` 自带后验预测模型，
进程内环境 `world.py` 也只依赖 `belief.py`。它作为问题4 的信念建模留档保留，
若不再需要可以删除。

## 3. 分层与依赖方向

依赖单向，箭头指向被依赖方：

```
deploy.py / eval.py / e2e_test.py / oracle_route.py     入口（命令行）
        |
        v
sweeper.py（问题3 规划器） / sweeper4.py（问题4 规划器）
        |
        v
ops.py + belief.py（问题3）   scan4.py + belief4.py（问题4，留档）
        |
        v
world.py（进程内环境）   ../consts.py（物理常量）
```

脚本一律以 `python -m robotdog.solver.<模块>` 从仓库根目录运行，不需要各自推算仓库路径。
模拟器 `simulator/` **刻意不共享** `consts.py`：两份常量各自独立，才能让逐动作等价性
测试（`tools/tests/test_solver_equiv.py`）有意义。

## 4. 怎么跑

```powershell
# 问题3 进程内评测（多核）
python -m robotdog.solver.eval --seeds 9500-9599

# 部署 / 正式测试（问题3 或 问题4）
python -m robotdog.solver.deploy --team-id <参赛队号> --problem 3
python -m robotdog.solver.deploy --team-id <参赛队号> --problem 4

# 真实进程 + HTTP 端到端验收
python -m robotdog.solver.e2e_test --problem 4 --runs 3
```

批量与取数走 `tools/`（问题3：`candidates.py` / `eval_deploy.py`；问题4：`eval_q4.py` /
`tune_q4.py`）；论文插图与审计探针见 `tools/probes/`。

## 5. 两个必须分清的口径

1. **现实时间才是约束**：`/enter` 返回的 `remaining_real_duration_s`（20 min）由
   `client.py` 统一读取，其它模块不得自算时间口径。100 h 是虚拟世界活动时长上限，
   只用于防死循环，实测每局只用掉约 1%。
2. **部署口径 vs 进程内口径**：正式测试屏蔽真值总数，只能靠信念判据决定何时停机
   （`knows_total=False`）；进程内评测知道总数，清完即停（`knows_total=True`）。
   任何结论都应同时报两个口径的数字。
