# 问题3 解题思路（简要）

> 本文是问题3 策略的简要说明：建模、核心洞察、算法主循环、关键机制与结果。
> 完整技术细节与工程要点见 `../robotdog/solver/README.md`，
> 代码见 `../robotdog/solver/sweeper.py`。

---

## 1. 题目要求（问题3原文口径）

目标区域是半径 1800 m 的圆域，场内为**全向干扰源**，总数在 **10–16 个**之间但具体个数未知；
机器狗从原点出发、测向机初始频道为 1，要求**自动搜索、定位并清除全部干扰源**，
在确保全部清除的前提下**总时间越短越好**。评价指标：

| 指标 | 定义 |
| --- | --- |
| 清除比例 | 被清除干扰源个数 / 干扰源总数 |
| 平均定位清除时间 | 定位清除总时间 / 被清除干扰源个数 |

其中定位清除总时间包含移动、频道切换、检测、光学精确定位与清除时间。

题目给定的关键物理规则（决定策略形态）：

| 规则 | 数值/含义 |
| --- | --- |
| 移动 | 5 m/s，沿直线 |
| 一次检测 | 停止 + 切换频道 1 s + 检测 5 s |
| 清除 | 需逼近到 **20 m** 内；光学定位 3 s + 激光清除 2 s |
| 距离 ≤ 5 m | 返回 `near`（无示向度），可直接定位清除 |
| 示向度误差 | ∈ [−1°, 1°]；**同一地点重复检测读数不变**（同点重测零信息） |
| 有效接收半径 R | 每个源在 1000–1500 m 内随机，**不返回**；超过 R 收不到信号 |
| 频道 | 每个源频道互不相同，取自 1–20，源个数未知 |
| 时间上限 | 现实程序运行 20 min、测试窗口 25 min；虚拟活动 100 h 仅为防死循环 |

## 2. 问题本质：为什么不能"先搜完再清"

把题目翻译成决策问题，有三条结构性结论：

1. **真值不可观测**：源的位置、频道、R、个数都不知道，只有检测结果可观测，
   本质上是 **POMDP**。因此方案拆成「**贝叶斯估计（信念）**」+「**确定性规划（决策）**」两层。
2. **时间主项是移动**：单局虚拟时间 3007 s（30 局均值）中，移动约 **71%**（2148 s），
   检测（5 s/次，一局约 135 次）约 22%，频道切换约 5%，清除约 2%。
   所以全部难点是**少走路**。
3. **漏源比慢更不可接受**：平均时间 = 总时间 / 清除个数，漏一个源会**双重惩罚**
   （分子不变、分母变小）。因此"清掉一个源"的价值远高于省下的几百秒。

另外，现实程序运行时间实际只用了约 **0.1 s / 1200 s**（虚拟时间约用掉 1.2%），
**时间预算远远用不完，真正的瓶颈是"还能不能找到剩下的源"**。

## 3. 核心洞察：清除即探测（把探测点放在刚清除的源上）

这是整个策略的主线，其余机制都由它推出：

> 留出集里平均每局 **13.1 个源**，均匀分布在 r = 1800 m 的圆域里：
> **最近邻距离中位 451 m（均值 494 m），第 3 近邻中位 944 m（均值 992 m）**；
> 而有效接收半径 R ≥ 1000 m。
>
> 因此**站在一个刚清除的源上测其它频道，对附近未发现的源几乎是"必中"**
> （d ≤ 1000 m 时收到概率为 1），而且这一步**不产生任何额外移动**。

反面对照：在"去目标路上 60% 处"检测（命中率约 0.3）或专程跑到网格点检测，
实测每局有约 104 次 `no_signal`（约 624 s）外加约 4740 m 专程探测移动（约 948 s），几乎全是浪费。

于是搜索与清除合成为同一趟路：**永远就近清除已知源（路线≈TSP），清完就地补测其它频道。**

## 4. 模型框架

### 4.1 估计层：三种信念表示（`belief.py`）

| 观测情况 | 表示 | 更新方式 |
| --- | --- | --- |
| 尚未收到任何示向度 | 100 m 分辨率占用网格 | `no_signal` 乘核 `P(R<d)=clamp((d−1000)/500)` |
| 只有 1 条示向度 | 沿射线的 128 个一维样本（径向密度 ∝ r·P(R≥r)） | 一维重加权 + 系统重采样（固定相位，可复现） |
| ≥ 2 条示向度 | Gauss–Newton 角度残差最小二乘 + 解析协方差 | `Σ = (JᵀJ/σ² + 先验)⁻¹`，σ = 0.5774° |

同时为每个频道维护"存在未清除源"的概率 π_c，用 `P(观测 | 存在)` 做贝叶斯更新，
Σπ_c 即**剩余源数的期望**——这是正式测试（看不到真值总数）下唯一可用的收手依据。

> 不用粒子滤波：±1° 是硬约束，一条射线把后验压成宽约 20 m 的窄楔形，
> 在 10⁷ m² 上放 200 个粒子，落在楔形内的期望不足 1 个，必然退化（已实测确认）。

### 4.2 决策层：动作原语

| 原语 | 定义在 | 语义 |
| --- | --- | --- |
| `pursue(c)` | `ops.py` | 对频道 c 执行"逼近—检测—清除"子策略，直到清除或失败 |
| `choose_measure_point` | `ops.py` | `pursue` 内部的一步前瞻贪心，决定"下一点测哪里" |
| `probe(p, chans)` | `ops.py` | 移动到点 p，对筛选后的频道做一轮检测 |
| `pursue_fast(c)` | `sweeper.py` | 沿视线推进（本来就要走的路）。只在需要时做一次**弦式侧移**：在剩余路段中点按后验纵深不确定度定标侧移 δ（限制在 10~400 m），把纵向距离定下来；更远时只按约 500 m 步长推进，不额外绕行 |
| `best_info_point` | `sweeper.py` | 需要专程探测时，按 **净收益 = 信息价值 − 旅行 − 检测** 选点，亏本的不去 |
| `joint_measure_point` | `sweeper.py` | 把"顺路停车点"与"弦式侧移"合并成一次 `(ε, δ)` 联合选择 |

单次检测只约束"源在某条射线上"（横向准、纵向完全未知）。所以要压缩最不确定方向 v，
新检测点的**视线必须与 v 垂直**（沿视线挪动零信息）；再乘上检测概率权重，
才不会退化成原地反复检测同一点。

### 4.3 主循环（`sweeper.run_sweeper`）

```
1. 起点盲扫一次            （原点覆盖半径 1000~1500 m，约命中一半源）
2. 有已定位目标 → 就近清除  （TSP 排序，逼近途中只测目标频道用于定位）
3. 清除成功后 → 原地补测其它可疑频道（零移动，收益最高的一步）
4. 没有已知目标 → 按信息净收益专程探测；都不划算则按集合覆盖扫残余质量
5. 收尾：残余期望源数 < hunt_mass_min，或连续多次探测无收获则收手
```

对应流程图见 `figures/q3_flow.png`。

## 5. 关键机制与参数

| 机制 | 作用 |
| --- | --- |
| 起点盲扫 | 原点一次把可能频道测一轮，单位时间发现率最高，先拿到一批"种子目标" |
| 就近清除 + TSP | 目标排序用 2-opt 巡回；但**不用真值 TSP**——单射线目标不确定度大，静态最优巡回反而慢 |
| 清除后原地补测 | 核心洞察的落地：零移动、高命中，是清除率的主要来源 |
| 弦式侧移 | 在剩余路段中点做一次侧移检测（δ 按后验纵深不确定度定标，限制在 10~400 m），取代"走到估计点旁固定 30 m 再折返"的来回 |
| 单点联合选择 | 把"顺路停车点"与"弦式侧移"合并成一次 `(ε, δ)` 联合优化，候选集恒含保守动作 |
| 收尾集合覆盖 | 无划算信息点时，按覆盖最多残余质量选点，一趟测满全部频道（旅行成本不变） |
| **收尾闸门 `hunt_mass_min`** | **唯一重要旋钮**：残余期望源数低于该值即收手。残余期望源数在 [0.02, 0.20) 时每次专程探测命中率仅 0.9%~3.2%，代价却是 166~203 s 往返，因此按"清除比例 ≥ 0.98"标定为 **0.20** |

## 6. 结果

**留出集 seed 9500–9799（300 局，确定性执行）：**

| 口径 | 清除比例 | 全清局数 | 平均定位清除 | 移动 |
| --- | --- | --- | --- | --- |
| **部署（正式测试口径，被打分）** | **0.9982** | 293/300 | **259.7 s/源** | 12067 m |
| 进程内（知道总数，清完即停） | 0.9982 | 293/300 | 241.0 s/源 | 11153 m |

- 距验收门槛 0.98 有 **+0.0182** 余量（300 局漏 7 个源，门槛允许 78 个）。
- 泛化检验（seed 8000–8099，从未参与标定）：部署口径 **0.9953 / 261.7 s/源**。
- 端到端（真实进程 + HTTP + 真值屏蔽）：单局清除率在 **93%~100%** 波动（与留出集漏源同源），
  现实程序运行时间约 0.1 s / 1200 s。

以上数字的原始逐局明细在 `../data/reports/q3_insample.json`（进程内）与
`q3_deploy.json`（部署）；收尾闸门前沿与泛化集在 `pareto_p3.json` / `pareto_p3_gen.json`。

> **两个口径不能混比**：进程内看得到真值总数，清完立刻停；部署（正式测试）看不到，
> 还要额外花时间确认。被打分的是**部署口径**。

## 7. 踩过的坑（结论式提醒）

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 粒子滤波完全退化 | ±1° 硬约束下窄楔形占全域 0.4%，200 粒子必然只剩 0–1 个 | 改三表示混合信念 |
| 协方差只有 9 m 但真值差 400 m | 信息矩阵漏了 σ² 量纲 | `Σ=(JᵀJ/σ²+先验)⁻¹` |
| 原地反复检测同一点 | 不知道"同点同频道读数不变" | 记录已测点并排除；不确定度按检测概率加权 |
| 已定位源被放弃、清除率卡 98% | R 的后验只用了 `no_signal` 的上界，漏了"收到过信号"的下界 | `r_bounds()` 同时用两侧观测 |
| 同一案例两次跑出 13% 抖动 | 射线重采样用了无播种随机数 | 改系统重采样（固定相位） |
| 个别种子跑成上万秒、只清一半 | `pursue_fast` 没有停滞保护，假轨迹被无限重试 | 连续 3 步没有新观测就放弃；外层再加"拉黑该频道" |
| "优化得更优"的巡回反而慢 | 单射线目标不确定度大，静态最优解会派狗去远处省名义长度 | 保留最近优先启发式 |

**一句话总结**：问题3 的策略是"**清除即探测**"——用贝叶斯信念估位置与剩余源数，
永远就近清除已知源，并在每次清除后原地补测其它频道（零移动、高命中），
只在没有已知目标时才专程探测或按集合覆盖收尾；用收尾闸门在"漏源"与"耗时"之间取舍。
