# 模拟器设计说明（对照题目要求逐条实现）

本文说明自建模拟器 `simulator/` 的实现口径，逐条对应 B 题正文、附录与附件1、附件2 的要求，
并列出实现中需要自行假设的部分（题目未给出具体分布时）。

## 1. 总体架构

```
        ┌────────────────────────────┐        ┌──────────────────────────┐
        │  机器狗程序 python -m robotdog.solver.deploy │      │  模拟器界面 gui.py       │
        │  (HTTP+JSON 客户端)        │        │  (网页控制台 :2027)      │
        └─────────────┬──────────────┘        └───────────┬──────────────┘
                      │  POST /enter /measure /clear /exit │ 控制/状态/导出
                      ▼                                    ▼
        ┌──────────────────────────────────────────────────────────────┐
        │ server.py  HTTP 层: 路径/方法/Content-Type/请求体/幂等/状态码 │
        ├──────────────────────────────────────────────────────────────┤
        │ core.py    引擎: 物理规则 + 虚拟时钟 + 案例 + 报告 + 加密日志 │
        ├──────────────────────────────────────────────────────────────┤
        │ session.py 会话: 登录校验 + 四个模块 + 25 分钟窗口 + 日志队列 │
        └──────────────────────────────────────────────────────────────┘
```

三条计时线彼此独立，均按题目设定实现：

* **现实时间**：用户确认开始 → 模拟器准备案例 → 5 秒倒计时 → 开放 25 分钟窗口与接口；
  `/enter` 成功后开始计算 20 分钟程序运行时间，实际截止时刻为两者较早者；
  `/enter` 响应中的 `remaining_real_duration_s` 即真实可用现实秒数（0~1200）。
  **20 分钟是"现实程序运行时间"的上限，不是虚拟时间上限。**
* **虚拟时间**：只有 `accepted=true` 的 `/measure`、`/clear` 推进；
  内部按微秒累计，响应最多保留 6 位小数。
* **虚拟世界活动时长**：上限为 **100 小时 = 360000 s**（附件1 2.5：机器狗在虚拟世界的活动时长
  通常不构成约束，设定上限只是为了防止程序死循环）。它与现实限时相互独立，
  两者任一到达都会结束测试，以较早到达者为准。

> 常见误解澄清：`max_virtual_duration_s = 360000`（100 小时）**不是** 20 分钟；
> 20 分钟对应 `/enter` 响应里的 `max_real_duration_s = 1200` 与
> `remaining_real_duration_s`。机器狗程序控制节奏时应使用后者。

## 2. 逐条实现对照

### 2.1 干扰源（附录1）

| 要求 | 实现 |
| --- | --- |
| 频道互不相同、位于 1..20 | `CaseGenerator`：`random.sample(range(1,21), n)` |
| 干扰源个数 10~16 且未知 | `n = randint(10,16)`；接口不返回个数与真值 |
| 全向源覆盖 360° | `kind="omni"`，`in_coverage` 恒为真 |
| 定向源覆盖「定向方向两侧各 90°（含）」 | `abs(((bearing-dir+180)%360)-180) <= 90`（含边界） |
| 覆盖角内场强仅随距离衰减、与角度无关 | 收到信号时示向度恒为「检测点 → 干扰源」的真实方位角 |

### 2.2 测向机（附录2 第2节）

| 要求 | 实现 |
| --- | --- |
| 示向度 = 最大场强方向方位角，$[0°,360°)$ | `InterferenceSource.true_bearing` |
| 误差范围 $[-1°,1°]$ | `SimulatorEngine._default_error`，由 `sha256(run_id, x, y, channel)` 映射到 $[-1°,1°]$ |
| 同一地点重复检测不改变误差 | 误差只与（本次运行、检测点、频道）有关，同点重复检测读数完全一致 |
| 不同地点呈现统计规律 | 不同检测点误差各不相同（见 `tests/test_physics.py::SvDErrorTest`） |
| 有效接收半径 1000~1500 m，接口不返回 | `radius_m = uniform(1000,1500)`，仅写入真值报告 |
| 距离 > 半径无信号 | `_do_measure` 距离判定 |
| 距离 ≤ 5 m 且在覆盖角内 → `near` | `NEAR_RADIUS_M = 5.0` |
| 频道 1..20，`1.0` 视为合法、`1.5` 返回 400 | `_check_channel` |
| `/clear` 不切换频道、不产生切换耗时 | `_do_clear` 不写 `run.channel`，`switch_s = 0` |

### 2.3 计时（附件1 表1、附件2 第4节）

| 动作 | 耗时 | 实现 |
| --- | --- | --- |
| 移动 | 直线距离 / 5 m/s | `travel_seconds` |
| 切换频道 | 1 s，仅 `/measure` 且频道不同时计入 | `_do_measure` |
| 检测 | 5 s，三种结果均为 5 s | `DETECT_DURATION_S` |
| 清除未发现 | 3 s（仅光学精确定位） | `CLEAR_LOCATE_S` |
| 清除成功 | 5 s（3 s 定位 + 2 s 激光清除） | `CLEAR_LOCATE_S + CLEAR_FIRE_S` |
| `/enter`、`/exit` | 0 s | 不推进虚拟时钟 |

题目示例（附件1 表2、附件2 第10节）的 105 / 111 / 194 / 199 s 在
`tests/test_physics.py::TimingTest::test_full_timing_example` 中逐项断言。

### 2.4 通信协议（附件2 第5~9节）

* **HTTP 方法/路径**：仅 `POST`，路径精确匹配，尾随斜线与查询参数返回 404；
  已知路径的其他方法（GET/HEAD/PUT/DELETE/PATCH/OPTIONS）一律返回 405，
  未知路径的其他方法返回 404。`HEAD` 只返回状态行与头部，不带响应体。
* **Content-Type**：`application/json`，可选且仅可带 `charset=utf-8`（大小写不敏感），其余 415；
  `Content-Encoding` 仅允许省略或 `identity`，其余 415。
* **请求体**：UTF-8 无 BOM，最大 65536 字节（超限 413），JSON 对象、禁止重复键、
  禁止 `NaN/Infinity` 字面量、嵌套 ≤ 16 层，否则 400。
* **字段**：未声明字段（含 `position` 下的未知字段）返回 HTTP 200 + `accepted=false`；
  缺少必填字段、类型错误、频道越界、坐标非有限或越界、标识符为空/超长/含控制字符返回 400。
* **错误响应体口径**：任何 `accepted=false`（无论是 HTTP 4xx 错误还是业务拒绝）
  都返回 `virtual_time_s = 0`。附件2 4.1 明确要求不要把该 0 当作当前虚拟时刻；
  需要虚拟时刻时应使用最近一次 `accepted=true` 的响应。
* **幂等**：同一 `request_id` 且内容相同 → 返回首次完整响应且不重复推进时间；
  内容或路径不同 → 409；结构错误、未知字段、`arena_id`/`robot_id` 不匹配不占用 ID。
* **串行化与并发**：附件2 表2 规定"并发发送了不同动作 → 409"。
  引擎内置**串行闸门**：同一时刻只允许一个动作在引擎内执行；
  并发到达的**不同**新动作立即返回 409（`accepted=false`、`virtual_time_s=0`）；
  并发到达的**同一动作重试**（同 `request_id` + 同内容 + 同路径）会等待在途动作结束，
  然后按幂等规则返回首次响应，不重复执行。
  服务端持续统计"引擎内同时执行的动作数"，该值必须恒为 1（`max_concurrent`），
  可用 `SimulatorServer.concurrency_stats()` 查询，用于自检机器狗程序是否真的串行发送。
* **业务拒绝**：HTTP 200 + `accepted=false`，响应体与附件2 §5.2 严格一致，
  只含 `accepted`、`real_timestamp_ms`、`virtual_time_s`（=0）三个字段。
  调试时可设置 `SimulatorEngine.verbose_reject = True`，额外返回
  `reject_code` / `reject_message`（正式测试建议保持关闭）。
* **接口未开放**：倒计时未结束、测试结束、测试中止时，`/enter`、`/measure`、`/clear`、`/exit`
  均返回 `accepted=false`（`not_open` / `test_ended`）。

### 2.6 案例真值的保密（附件1 4.6）

"正式测试在任何界面和完成提示中都不显示案例真值"这一约束在**服务端数据层面**实现，
而不是只在界面上不渲染：

* `SimulatorEngine.status()` 仅在演练测试返回 `source_total`，正式测试返回 `null`；
* `SessionManager.ui_state()` 对正式测试的 `last_report.stats` 掩码
  `source_total`、`cleared_ratio`（置 `null`），`truth` 只返回 `{"hidden": true}`，
  `uncleared` 置空；
* `ModuleState.to_dict()` 对正式测试模块的历史记录完全不返回 `total` 字段。

因此即使直接抓取控制接口 `/api/state` 的 JSON，也无法反推出干扰源总数。
正式测试的真值只写入加密行为日志（供赛后核验），不进入任何在线接口。

### 2.5 测试流程（附件1 第4节）

| 要求 | 实现 |
| --- | --- |
| 四个测试模块 | `MODULES`：`q3_practice`、`q4_practice`、`q3_formal`、`q4_formal` |
| 演练不限次数、正式各 3 次 | `ModuleState.attempts_used/max_attempts`，正式测试启动即占用一次 |
| 启动前校验登录与服务器时间 | `LoginClient.verify()`（联网模式校验偏差 ≤ 60 s） |
| 5 秒倒计时后开放接口 | `SimulatorEngine.arm()/tick()` |
| 25 分钟窗口 + 20 分钟程序运行 | `window_deadline`、`real_deadline`，取较早者 |
| 虚拟世界活动时长上限 100 小时 | `max_virtual_s = 360000`，仅用于防止程序死循环 |
| 超时/中止结束测试并关闭接口 | `end_run()` 后 `phase=ended`，后续请求 `accepted=false` |
| 测试案例编码 | `C<日期>-P<题号>-<8 位十六进制>` |
| 演练结束显示真值、正式不显示 | `SimulatorEngine.status()/SessionManager.ui_state()` 按 `official` 屏蔽 |
| 正式测试生成加密日志并加入上传队列 | `export_log(official=True)` → `.log`（`ENC1` 魔数 + zlib + SHA256 流密码 + CRC32） |
| 日志 < 2 MB | `LOG_ENCRYPT_MAX_BYTES` 校验并在界面标注 |
| 机器狗自行记录行为日志 | `python -m robotdog.solver.deploy --log` 输出 JSONL（模拟器不提供该功能，与附件1 4.6 一致） |
| 17:30 后不能启动新测试 | `SessionManager.deadline_blocked()`，由 `--enforce-deadline` 启用 |

## 3. 题目未明确、本实现自行约定的部分

1. **随机分布**：题目只给出取值范围，未给出分布。本实现取
   圆域内均匀位置、半径 `U(1000,1500)`、频道 `1..20` 等概率无重复抽样；
   问题4 中每个干扰源以 1/2 概率为定向源，定向方向 `U(0°,360°)`。
2. **示向度误差的具体分布**：题目只给出范围，本实现取「同一检测点固定、不同检测点独立」的
   确定性伪随机值，从而满足「同一地点重复检测不改变误差」。
3. **成功/拒绝响应字段集**：默认与附件2 表4/表6/表8/表10 与 §5.2 精确一致，
   不附加任何非标准字段（早期版本的 `distance_m`、`all_cleared` 已删除；
   `reject_code`/`reject_message` 改为 `verbose_reject` 开关，默认关闭）。
4. **加密算法**：官方模拟器的加密方式未公开，本实现采用自描述格式
   （`ENC1` + 长度 + zlib 压缩 + SHA256 计数器流异或 + CRC32），仅用于本地校验与演示。
5. **联网登录**：官方服务器接口未公开，`online` 模式预留 `POST /login`、`GET /time` 两个端点，
   默认使用 `offline` 模式在本地完成校验。
6. **并发判定的实现方式**：附件2 只规定"并发发送了不同动作 → 409"，未规定判定细节。
   本实现以"引擎内是否已有动作在执行"为唯一判据，并以
   `request_id` + 内容指纹识别"同一动作的重试"（网络重试必须复用原 ID 与内容）。

## 4. 机器狗程序策略

模拟器只负责环境与协议，本工程提供的机器狗侧决策在 `robotdog/solver/`：

1. **问题3（`sweeper`）**：起点盲扫 → 就近清除已知源（逼近途中只测目标频道用于定位）
   → 清除后原地补测其它频道（零移动）→ 无已知目标时按信息净收益专程探测
   → 残余期望源数低于收尾闸门即收手。信念用「网格 / 射线样本 / Gauss-Newton」三表示维护。
2. **预算管理**：以 `/enter` 的 `remaining_real_duration_s`（**现实**口径）为准；
   虚拟 360000 s 上限只是防死循环的兜底，不参与决策。
3. **时间口径**：两者相互独立，现实 1 秒可推进任意多虚拟秒 ——
   详见 `README.md` 文首的 WARNING 框与 `docs/验收报告.md` §5。

模拟器本身按附件1 实现问题3 / 问题4 两个环境（含定向源规则），不随求解器取舍而裁剪。
策略细节见 `docs/问题3论文.md` 与 `robotdog/solver/README.md`。
